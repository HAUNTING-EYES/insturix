Motion graphics is NOT just lower-thirds and stat counters. STOP reducing the scope to individual graphic types.

**Why:** The agent kept proposing "build LowerThird component, build KeywordHighlight component" — treating motion graphics as a small set of named templates to code one by one. This misses the entire domain. Motion graphics includes: title sequences, animated infographics, data visualizations, kinetic typography, animated logos, transition graphics, split screens, comparison tables, process flows, testimonial cards, price tables, CTAs, subscribe animations, before/after reveals, timeline/chronology, progress indicators, animated maps, character animations, picture-in-picture, end cards, and more.

**How to apply:** When working on motion graphics, think SYSTEM not COMPONENT. The architecture should generate ANY motion graphic from parameters (brand signals, content signals, content type). Individual components are instances of the system, not the system itself. The VIE (Structure × Theme + GSAP) is the system. Don't plan "build LowerThird.tsx, then KeywordHighlight.tsx" — plan "build the motion graphic generation system that CAN produce lower-thirds, keyword-highlights, infographics, title sequences, and anything else from tokens."
