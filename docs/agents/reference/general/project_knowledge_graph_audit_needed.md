# Creative Knowledge Graph Audit — NEEDED

**Priority:** P0 for Mode 2 quality
**Flagged by user:** 2026-05-14
**Why P0:** The signal executor evaluates 95 graph mappings. The constraint enforcer checks 50 constraints. The genre parameter computer uses graph constants. If ANY threshold, constant, or mapping trigger is wrong, every Mode 2 project produces bad output.

## What needs auditing

### 218 Constants (Part 6)
Every hardcoded number in the graph needs verification against actual industry standards:
- LUFS targets (are they EBU R128 compliant?)
- Safe zones (are platform specs current for YouTube/TikTok/Instagram 2026?)
- Frame rate constants, transition timing defaults
- Pacing ranges per content type (are these real editorial standards or LLM-generated?)

### 95 Mappings (Part 2)
Each mapping has a trigger condition, technique reference, and weight response:
- Are the trigger thresholds right? (e.g., "speech.energy > 0.7" — is 0.7 the right threshold?)
- Are the techniques correct for the trigger? (e.g., does high motion ACTUALLY call for zoom-punch?)
- Are the anti-patterns real? (or were they hallucinated when building the graph?)

### 50 Constraints (Part 4)
Each constraint limits what techniques can do:
- Are the limits real? (e.g., "max 3 dip-to-black per video" — is that an industry standard?)
- Are there constraints MISSING that should exist?
- Are any constraints too aggressive (killing good decisions) or too permissive (letting bad ones through)?

### 49 Signals (Part 1)
Each signal has a detection method and threshold:
- Are the thresholds calibrated to real data?
- Does the signal actually fire when it should for real content?

### 71 Theory Nodes (Part 5)
References to Murch, Eisenstein, Pearlman:
- Are the citations accurate?
- Are the extracted principles correctly operationalized?

## How to audit
1. Sample 20-30 constants → verify against authoritative sources (EBU specs, platform docs, Murch's book)
2. Run 5 diverse test videos through the signal executor → log which mappings fire → check if the decisions make editorial sense
3. For each mapping that fires on bad content, trace: trigger condition → was the signal reading correct? → was the threshold right? → was the technique appropriate?
4. Compare constraint limits against what a real editor would allow

## Known symptoms (from user)
- "Hallucinated values" — numbers that were generated by LLM, not sourced from real standards
- "Constants tampering with output" — wrong thresholds cause wrong decisions
- "Strategic decisions" — mapping logic that sounds reasonable but produces bad results in practice
