## What the corrected run establishes

The V3R3 benchmark defects were actually removed before this run:

- the provider-visible API declares layer-kind bindings;
- translation units are declared as CSS pixels;
- the verifier rejects component/layer-kind mismatches before execution;
- rendered acceptance measures all six requested motion directions rather than
  one hidden authored recipe; and
- the accepted model source is carried unchanged through the owner, verifier,
  deny-all sandbox, generated render and hybrid continuity proof.

Every Luna and Terra response passed the corrected source contract. Eleven of
the twelve OpenAI programs produced measurable rendered output; four passed all
frozen predicates, seven failed visible entry/exit motion, and one failed
runtime validation before a valid proxy was produced. The repeated motion
failures are therefore model/program outcomes under this contract, not the old
missing-unit or missing-kind confound.

The successful outputs prove that both Luna and Terra can sometimes synthesize
this bounded generated-composition program from the supplied contract. The
failure rate proves they do not yet do so reliably enough for unattended
production use.

## Budget-arm caveat

The capability-ceiling arm authorised up to two source candidates and one
verifier-triggered repair. In this run every Luna and Terra source passed the
static source verifier on its first provider response. Consequently, no repair
was triggered and every row committed one provider request. The arm did not
feed rendered-motion failures back to the model.

It would be false to interpret the arm comparison as a measured render-repair
curve. A later repair experiment must freeze which rendered diagnostic may be
returned, preserve the original candidate, cap attempts explicitly and score
quality, latency and spend per repair ordinal.
