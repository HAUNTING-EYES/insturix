## Scope correction — native multimodal model first

The fourteen-image arm below remains an immutable **sparse control**. It is no
longer the intended primary reference-understanding path and is not awaiting
dispatch as a prerequisite to that path. Its purpose is limited to provider
image-serialization parity, weak-evidence behaviour and fallback diagnostics.

The primary HREF path is now:

1. submit the original hash-bound reference video, including its embedded
   audio, to Gemini 3.7 Flash through its native video modality;
2. require one closed, timestamp-cited observation covering global editorial
   language, recurring grammar, bounded hero moments, content literals,
   temporal/audio behaviour and uncertainty;
3. request dense follow-up only for short model-identified or evaluator-
   required windows whose exact motion, transition, mask, text or audio claim
   is not established by the whole-video pass; and
4. evaluate omissions, inventions, timestamp accuracy and protected-literal
   separation against a preregistered full-video rubric.

Luna and Terra are not raw-video arms because their current API model contracts
accept images but not video or audio. They may later receive the verified
reference observation as planning input or participate in an explicitly
image-based fallback/control condition. The benchmark must not claim modality
parity where none exists.

Phase 1 adds only the validated, hash-bound Gemini native-MP4 transport through
the existing provider codec. No native-video model inference, semantic score or
product capability is claimed yet. The production path will use provider file
upload/reuse for larger references; the inline MP4 transport is bounded test
plumbing, not the long-form media authority.

## Why exactly fourteen frames

The source contains 3,885 video frames. Fourteen sampled images are about
0.36 percent of those frames. They were chosen as a deliberately sparse first
arm at 0.5, 5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60 and 64.25 seconds.

This arm asks a narrow question: can each provider receive the same ordered,
timestamped, hash-bound images and produce broad, evidence-cited observations
without being shown the evaluator or editing tools? It is useful for catching
the earlier tiled-contact-sheet ambiguity and for testing provider
serialization cheaply.

Fourteen frames are **not enough for production reference understanding**.
They can miss short events and cannot establish continuous motion, exact
timing/easing, transitions between samples, or any audio relationship.
Production evaluation must add separate native-video/audio and adaptive dense
inspection arms, measure missed material against densely annotated ground
truth, and calibrate its sampling policy. The generic 64-frame input ceiling is
a transport guard, not a production quality target.

## What this proves

- The exact tracked source can be materialized reproducibly in the current
  benchmark environment.
- Every extracted frame matches the frozen byte length and hash.
- Frame order and microsecond timestamps survive provider serialization.
- Provider-visible task material and evaluator-only expectations remain
  separate.
- Malformed or drifted source/tool/frame evidence stops before dispatch.

## What this does not prove

- No model has analyzed this reference.
- No reference-understanding, editorial-planning or editing score exists.
- Sparse frames cannot establish audio, exact easing, continuous motion,
  transition microtiming or unsampled events.
- A single reference cannot establish general editing competence.
- Repository provenance is not a legal-clearance opinion; provider egress
  requires a separate operator authorization.
